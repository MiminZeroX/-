# คู่มือการลบข้อมูลและล้างฐานข้อมูล ระบบจองห้องประชุม

**สำนักงานเขตบางรัก กรุงเทพมหานคร**

คู่มือปฏิบัติงานเล่มนี้รวบรวมวิธีลบข้อมูลทุกประเภทในระบบจองห้องประชุม ตั้งแต่การลบรายการเดียว การล้างการจองตามระยะเวลาเก็บข้อมูลส่วนบุคคล การล้างข้อมูลทดสอบก่อนเปิดใช้จริง การกู้คืนเมื่อลบผิด การรีเซ็ตทั้งระบบ ไปจนถึงการปิดระบบถาวรหลังส่งมอบ โดยยึดหลัก **สำรองก่อนลบ ลบเท่าที่จำเป็น และบันทึกทุกครั้ง**

ผู้ปฏิบัติต้องมีสิทธิ์ **ผู้ดูแลระบบ** ในหน้า admin และสำหรับส่วนที่ 3–4 ต้องมีสิทธิ์ในบัญชี Cloudflare และ GitHub ของระบบ

# ส่วนที่ 1 — ก่อนลบข้อมูล

## 1. ข้อมูลอะไรอยู่ที่ไหน

| เรื่องร้องเรียน/แจ้งปัญหา/ข้อเสนอแนะ    | ✓ (ถ้าผู้ส่งใส่)  | Cloudflare                                          | 5                   |

## 2. หลักปฏิบัติก่อนลบทุกครั้ง

1. **สำรองก่อนลบ** — ดาวน์โหลดไฟล์สำรองทุกครั้ง (หัวข้อ 3)
2. **ยกเลิกแทนลบ** — การจองจริงที่ไม่ใช้แล้วให้กด **ยกเลิก** เพื่อเก็บประวัติ ใช้ **ลบถาวร** เฉพาะรายการทดสอบ จองผิด หรือพ้นระยะเก็บข้อมูล
3. **ปิดใช้แทนลบ** — บัญชีผู้ใช้ที่ลาออกให้ **ปิดการใช้งาน** ก่อน เพื่อให้ประวัติใน Log ยังอ่านได้ชัดเจน
4. **ได้รับอนุมัติ** — การล้างข้อมูลจำนวนมาก การรีเซ็ตระบบ และการปิดระบบถาวร ต้องได้รับอนุมัติจากผู้บังคับบัญชา และแจ้งเจ้าหน้าที่คุ้มครองข้อมูลส่วนบุคคล (DPO)
5. **ทำนอกเวลาทำการ** — ลดผลกระทบต่อผู้ที่กำลังจองอยู่
6. **บันทึกการลบ** — กรอกแบบบันทึกในหัวข้อ 18 ทุกครั้งที่ล้างข้อมูลจำนวนมาก (การลบทุกแบบถูกบันทึกใน Log ของระบบด้วย)

## 3. ดาวน์โหลดไฟล์สำรองก่อนลบ

![สำรอง/กู้คืนข้อมูล](images/a-backup.jpg)

1. เข้าสู่ระบบหน้าผู้ดูแล › เมนู **สำรอง/กู้คืนข้อมูล**
2. ติ๊ก **รวมบันทึกกิจกรรม** (แนะนำเมื่อจะล้างข้อมูลจำนวนมาก)
3. กด **ดาวน์โหลดไฟล์สำรองตอนนี้** จะได้ไฟล์ชื่อลักษณะ `bangrak-booking-backup-20261102-0930.json` (วันที่เป็นปี ค.ศ.)
4. ตั้งชื่อโฟลเดอร์ตามวันที่และเหตุผล เช่น `สำรองก่อนล้างข้อมูล-2569-11-02` เก็บในไดรฟ์ของหน่วยงานที่จำกัดสิทธิ์
5. เปิดไฟล์ด้วยโปรแกรมแก้ข้อความ (Notepad/TextEdit) ดูให้แน่ใจว่ามีข้อมูล (มีคำว่า `"bookings"`) แล้วปิดโดยไม่แก้ไข

> ไฟล์สำรองมีข้อมูลส่วนบุคคล ห้ามส่งผ่านกลุ่มแชทหรืออีเมลส่วนตัว และไม่มีรหัสผ่านของผู้ใช้ (บัญชีผู้ใช้ไม่ถูกกู้คืนจากไฟล์นี้)

# ส่วนที่ 2 — ลบรายรายการ

## 4. ลบการจอง 1 รายการ หรือหลายรายการ

**1 รายการ**

1. เมนู **รายการจอง** › ค้นหาด้วยรหัสการจอง ชื่อ หรือวันที่
2. กดรายการเพื่อเปิดรายละเอียด › ปุ่ม **ลบถาวร** (สีแดง)
3. อ่านคำเตือน แล้วกด **ลบถาวร** อีกครั้ง

![รายละเอียดการจอง — ปุ่มลบถาวร](images/a-booking-detail.jpg)

**หลายรายการพร้อมกัน**

1. เมนู **รายการจอง** › เลือกแท็บหรือกรองให้เหลือเฉพาะรายการที่ต้องการ
2. ติ๊กช่องหน้ารายการ (ติ๊กช่องบนสุดเพื่อเลือกทั้งหน้า) จะมีแถบคำสั่งด้านล่าง
3. กด **ลบถาวร** › ยืนยัน (ครั้งละไม่เกิน 500 รายการ)

> การลบรายรายการ **ไม่สร้างไฟล์สำรองก่อนลบให้อัตโนมัติ** จึงต้องทำหัวข้อ 3 ก่อนเสมอ หากลบจำนวนมาก ให้ใช้หัวข้อ 10–11 ซึ่งสำรองให้อัตโนมัติ

## 5. ลบเรื่องร้องเรียน แจ้งปัญหา และข้อเสนอแนะ

![ร้องเรียน · ข้อเสนอแนะ — ไอคอนถังขยะอยู่ขวาสุดของแต่ละเรื่อง](images/a-feedback.jpg)

1. เมนู **ร้องเรียน · ข้อเสนอแนะ** › แท็บ **ทั้งหมด**
2. กดไอคอน **ถังขยะ** ขวาสุดของเรื่องที่ต้องการ (เห็นเฉพาะบัญชีสิทธิ์ผู้ดูแลระบบ)
3. อ่านคำเตือน แล้วกด **ลบถาวร** — ข้อความ ชื่อ และช่องทางติดต่อของผู้แจ้งจะถูกลบทันที

- ใช้เมื่อพ้นระยะเก็บที่หน่วยงานกำหนด (แนะนำ 1 ปีหลังดำเนินการเสร็จ) หรือผู้แจ้งขอให้ลบข้อมูล
- เรื่องที่ลบแล้วจะไม่นับในรายงาน KPI ของช่วงเวลานั้น จึงควรพิมพ์รายงาน KPI ก่อนลบ
- ไฟล์สำรองที่ทำไว้ก่อนหน้ายังมีเรื่องนั้นอยู่ (หัวข้อ 12) และการกู้คืนจากไฟล์สำรองจะ **ไม่** นำเรื่องร้องเรียนกลับมา

## 6. นำห้องออก และลบรูปห้อง

- **นำห้องออก:** เมนู **ห้องประชุม** › ปุ่ม **นำออก** ของห้องนั้น › ยืนยัน — ห้องถูกซ่อนจากผู้ใช้ การจองที่ยังไม่ถึงวันถูกยกเลิก แต่ประวัติการจองเดิมยังอยู่ (เพื่อรายงานย้อนหลัง)
- **ปิดชั่วคราวแทน:** ใช้สวิตช์ **เปิดให้บริการ** เมื่อห้องปิดซ่อมแล้วจะกลับมาใช้
- **ลบรูปห้อง:** **แก้ไข** › ช่อง **รูปห้อง** › **ลบรูป** › **บันทึก**

## 7. ปิดการใช้งาน หรือลบผู้ใช้

1. เมนู **ผู้ใช้งานระบบ** › เลือกผู้ใช้
2. **ปิดการใช้งาน** (แนะนำ) — เข้าสู่ระบบไม่ได้ทันที ชื่อยังแสดงใน Log
3. **ลบผู้ใช้** — ลบบัญชีถาวร ต้องยืนยันรหัสผ่านของท่าน ลบบัญชีตนเองไม่ได้ และต้องเหลือผู้ดูแลระบบอย่างน้อย 1 คน
4. ตรวจ GitHub Collaborators และ Cloudflare Members ของบุคคลนั้นด้วย (คู่มือผู้ดูแลฯ หัวข้อ 16, 22)

## 8. ลบหน่วยงานและวันหยุด

เมนู **หน่วยงานและวันหยุด** › กดลบรายการ › กด **บันทึกรายชื่อหน่วยงาน** หรือ **บันทึกวันหยุด** — การจองเดิมที่ใช้ชื่อหน่วยงานนั้นไม่เปลี่ยน

## 9. ล้างบันทึกกิจกรรม (Log) เก่า

1. เมนู **บันทึกกิจกรรม (Log)** › **ส่งออก CSV** เก็บไว้ก่อน (ถ้าหน่วยงานกำหนดให้เก็บหลักฐาน)
2. กด **ล้างบันทึกเก่า** › เลือก **ลบบันทึกก่อนวันที่** › กด **ลบบันทึก**

- ลบได้เฉพาะบันทึกที่เก่ากว่า **30 วัน** (ระบบล็อก 30 วันล่าสุดไว้เสมอ เพื่อให้ตรวจสอบย้อนหลังได้แม้บัญชีผู้ดูแลถูกใช้โดยมิชอบ)
- ระบบลบ Log ที่เกินระยะเก็บให้อัตโนมัติ (ค่าเริ่มต้น 365 วัน ปรับที่ ตั้งค่า › ระบบและความปลอดภัย › เก็บ Log)

# ส่วนที่ 3 — ล้างฐานข้อมูล และกู้คืน

## 10. ลบการจองเก่าตามระยะเก็บข้อมูลส่วนบุคคล

ใช้ทุกปีตามระยะเก็บที่หน่วยงานกำหนดร่วมกับ DPO (เช่น เก็บ 2 ปี)

1. พิมพ์หรือบันทึก **รายงาน KPI** ของปีที่จะลบไว้ก่อน (ตัวเลขสรุปจะหายไปพร้อมการจอง)
2. ดาวน์โหลดไฟล์สำรอง (หัวข้อ 3)
3. เมนู **สำรอง/กู้คืนข้อมูล** › การ์ด **ล้างข้อมูลการจอง** › เลือก **ลบการจองเก่า**
4. เลือกวันที่ — ระบบลบเฉพาะการจองที่ **วันประชุมอยู่ก่อนวันที่นี้** (เลือกวันในอนาคตไม่ได้) เช่น เลือก 1 ม.ค. 2568 เพื่อลบการจองทั้งหมดของปี 2567 และก่อนหน้า
5. ใส่ **รหัสผ่านของท่าน** › กดปุ่มสีแดง › ระบบแจ้งจำนวนที่ลบ
6. ระบบสร้างไฟล์สำรอง **`prepurge-วันที่เวลา.json`** ไว้ในรายการไฟล์สำรองอัตโนมัติก่อนลบเสมอ และบันทึก Log ระดับความปลอดภัย

## 11. ล้างการจองทั้งหมดก่อนเปิดใช้จริง

ใช้เมื่อทดสอบระบบเสร็จและจะประกาศใช้งานจริง

![ล้างการจองทั้งหมด: พิมพ์คำยืนยันและรหัสผ่าน](images/a-purge.jpg)

1. ดาวน์โหลดไฟล์สำรอง (หัวข้อ 3)
2. เมนู **สำรอง/กู้คืนข้อมูล** › **ล้างข้อมูลการจอง** › **ล้างการจองทั้งหมด**
3. พิมพ์คำว่า **ลบทั้งหมด** ในช่องยืนยัน และใส่รหัสผ่านของท่าน › กดปุ่มสีแดง
4. ลบเรื่องร้องเรียนทดสอบ (หัวข้อ 5) และผู้ใช้ทดสอบ (หัวข้อ 7) ด้วย
5. ตรวจว่าห้อง การตั้งค่า ผู้ใช้ หน่วยงาน วันหยุด และ Log **ยังอยู่ครบ** (คำสั่งนี้ลบเฉพาะการจอง)
6. รันโปรแกรมตรวจสอบระบบ 1 ครั้ง แล้วแจ้งเจ้าหน้าที่ทุกหน่วยงานว่าเริ่มใช้งานจริง

## 12. ลบผิด — กู้คืนข้อมูล

1. เมนู **สำรอง/กู้คืนข้อมูล** › **ไฟล์สำรองอัตโนมัติ** › หาไฟล์ `prepurge-…` (ก่อนล้างข้อมูล) หรือ `db-วันที่.json` (รายวัน) ที่ต้องการ › **ดาวน์โหลด**
2. ลากไฟล์นั้น (หรือไฟล์ที่ดาวน์โหลดไว้ในหัวข้อ 3) ไปวางที่ **กู้คืนจากไฟล์สำรอง** › ใส่รหัสผ่าน › ยืนยัน
3. ระบบสำรองข้อมูลปัจจุบันเป็น `prerestore-…` ให้ก่อน แล้วแทนที่การจอง ห้อง การตั้งค่า หน่วยงาน และวันหยุดด้วยข้อมูลจากไฟล์

> - การจองที่เกิดขึ้น **หลัง** เวลาของไฟล์สำรองจะหายไป จึงควรกู้คืนทันทีที่รู้ตัว หรือจดการจองใหม่ไว้แล้วเพิ่มกลับเอง
> - **บัญชีผู้ใช้และเรื่องร้องเรียน** ไม่ถูกแทนที่ด้วยการกู้คืน
> - ไฟล์สำรองอัตโนมัติถูกลบเองเมื่อเกินจำนวนวันที่ตั้ง (ค่าเริ่มต้น 30 วัน) ลบเองจากหน้าเว็บไม่ได้

## 13. รีเซ็ตทั้งระบบบน Cloudflare (เริ่มใหม่หมด)

ใช้เมื่อต้องการให้ **ทุกอย่าง** (ห้อง การตั้งค่า ผู้ใช้ Log ไฟล์สำรองอัตโนมัติ) กลับเป็นค่าเริ่มต้น — **ข้อมูลทั้งหมดใน Cloudflare หายถาวร กู้คืนได้จากไฟล์ที่ดาวน์โหลดไว้เท่านั้น**

1. ได้รับอนุมัติเป็นลายลักษณ์อักษร และดาวน์โหลดไฟล์สำรองรวม Log (หัวข้อ 3)
2. จดชื่อ Variables/Secrets ที่ใช้ (คู่มือผู้ดูแลฯ หัวข้อ 23) และตรวจ Settings › Builds (repository, branch `main`)
3. Cloudflare › **Compute** › **Workers & Pages** › `bangrak-room-booking` › **Settings** › **Danger zone** (ล่างสุด) › **Delete** › พิมพ์ชื่อ Worker เพื่อยืนยัน
4. สร้าง Worker ใหม่จาก repository เดิม (คู่มือผู้ดูแลฯ หัวข้อ 35 ส่วน Cloudflare) ใช้ชื่อเดิมได้
5. ตั้ง Secret `ADMIN_INITIAL_PASSWORD` **ก่อน** เปิดเว็บ (หัวข้อ 36) แล้วเข้าสู่ระบบและตั้งค่าใหม่
6. ถ้าต้องการข้อมูลบางส่วนคืน ใช้ **กู้คืนจากไฟล์สำรอง** (การจอง ห้อง การตั้งค่า หน่วยงาน วันหยุด) แล้วสร้างบัญชีผู้ใช้ใหม่
7. รันโปรแกรมตรวจสอบระบบ และพิมพ์โปสเตอร์ QR ใหม่หากที่อยู่เว็บเปลี่ยน

> ห้ามแก้ชื่อคลาส `TunnelTarget` หรือส่วน `migrations` ใน `wrangler.jsonc` เพื่อพยายามล้างข้อมูล — การ deploy อาจล้มเหลวหรือข้อมูลค้างอยู่ในคลาสเดิม ใช้วิธีในหัวข้อนี้เท่านั้น

## 14. ล้างข้อมูลแบบเครื่องในสำนักงาน / เครื่องคลาวด์ (VM)

1. ดาวน์โหลดไฟล์สำรองจากหน้าผู้ดูแล
2. ปิดระบบ (หน้าต่างสีดำ กด Ctrl + C หรือบน VM: `sudo systemctl stop bangrak-booking`)
3. ลบโฟลเดอร์ `data/` ในโฟลเดอร์ระบบ (มีฐานข้อมูล Log ไฟล์สำรอง และใบรับรอง HTTPS)
4. เปิดระบบใหม่ จะได้ระบบเปล่า พร้อมรหัสผู้ดูแลชั่วคราวในไฟล์ `data/initial-admin-password.txt`
5. ลบไฟล์ในถังขยะ (Recycle Bin / Trash) ของเครื่องด้วย เพื่อไม่ให้ข้อมูลส่วนบุคคลค้างอยู่

# ส่วนที่ 4 — ปิดระบบถาวร และข้อมูลส่วนบุคคล

## 15. ปิดระบบถาวร หรือลบระบบเดิมหลังส่งมอบ

1. ได้รับอนุมัติ และดาวน์โหลดไฟล์สำรองรวม Log เก็บตามระเบียบงานสารบรรณ
2. แจ้งผู้ใช้ล่วงหน้า และเปิด **ปิดรับการจองชั่วคราว** (ตั้งค่า › ระบบและความปลอดภัย) พร้อมข้อความแจ้ง
3. **ลบ Worker** ใน Cloudflare (หัวข้อ 13 ข้อ 3) — ข้อมูลทั้งหมดใน Cloudflare หายถาวร
4. ลบ Custom domain และระเบียน DNS ที่ชี้มายังระบบ (ถ้ามี)
5. **ลบ repository** (เมื่อไม่ต้องการเก็บโค้ด): GitHub › repository › **Settings** › **General** › **Danger Zone** › **Delete this repository** › พิมพ์ชื่อเพื่อยืนยัน — หรือเลือก **Archive this repository** หากต้องการเก็บโค้ดไว้อ่านอย่างเดียว
6. ลบ API Token, Personal Access Token และแอป Cloudflare ที่เชื่อมกับ GitHub (GitHub › Settings › Applications)
7. ลบไฟล์สำรองและรายงานในเครื่องส่วนตัวทั้งหมด (หัวข้อ 16)
8. กรอกแบบบันทึกการลบ (หัวข้อ 18)

## 16. ลบไฟล์สำรองและรายงานที่ดาวน์โหลดไว้

- ค้นหาไฟล์ชื่อ `bangrak-booking-backup-*.json`, `prepurge-*.json`, `db-*.json` ในโฟลเดอร์ Downloads ไดรฟ์ของหน่วยงาน และอีเมล
- ลบโฟลเดอร์ `checker/reports/` ในเครื่องที่เคยรันโปรแกรมตรวจสอบ
- ลบออกจากถังขยะ และจากไดรฟ์ออนไลน์ (Google Drive/OneDrive มีถังขยะของตนเอง ต้องลบซ้ำ)
- สื่อบันทึกภายนอก (USB) ให้ล้างหรือทำลายตามระเบียบของหน่วยงาน

## 17. เมื่อเจ้าของข้อมูลขอให้ลบข้อมูลส่วนบุคคล (PDPA)

1. รับคำขอเป็นลายลักษณ์อักษร ตรวจสอบตัวตนผู้ขอ และส่งเรื่องให้ DPO พิจารณา
2. ค้นหาข้อมูลของบุคคลนั้น
   - **รายการจอง** › ค้นหาด้วยชื่อหรือเบอร์โทร
   - **ร้องเรียน · ข้อเสนอแนะ** › แท็บ ทั้งหมด › ดูชื่อและช่องทางติดต่อใต้ข้อความ
3. ดาวน์โหลดไฟล์สำรองก่อน (หัวข้อ 3) แล้วลบรายการที่พบ (หัวข้อ 4–5) — การจองที่ยังไม่ถึงวันให้ยกเลิกและแจ้งผู้ขอก่อน
4. แจ้งผู้ขอว่าข้อมูลยังคงอยู่ในไฟล์สำรองอัตโนมัติไม่เกินจำนวนวันที่ตั้ง (ค่าเริ่มต้น 30 วัน) และในไฟล์สำรองที่หน่วยงานเก็บตามระเบียบ
5. แนะนำผู้ขอให้ลบข้อมูลในเครื่องของตนเอง: หน้า **การจองของฉัน** › **ลบจากอุปกรณ์นี้** และ **ตั้งค่าการแสดงผล** ของเบราว์เซอร์ › ล้างข้อมูลเว็บไซต์
6. ตอบผู้ขอภายในระยะเวลาที่กฎหมายกำหนด และบันทึกในแบบบันทึก (หัวข้อ 18)
