# ภาษาไทย · ส่วน ก — เริ่มต้นและภาพรวม

## 1. ระบบนี้คืออะไร และใครควรอ่านส่วนไหน

ระบบจองห้องประชุมออนไลน์ของสำนักงานเขตบางรัก สำหรับ **ห้องประชุมเล็ก ชั้น 2** และ **ห้องประชุมใหญ่ ชั้น 4**
เปิดผ่านเบราว์เซอร์ได้ทั้งคอมพิวเตอร์ แท็บเล็ต และมือถือ ไม่ต้องติดตั้งแอป

| คุณคือ                                             | อ่านส่วน                 |
| -------------------------------------------------- | ------------------------ |
| เจ้าหน้าที่ผู้จองห้อง                              | ก และ ข                  |
| ผู้ดูแลห้องประชุม / ผู้อนุมัติการจอง               | ก ข ค และ ซ              |
| ผู้แก้ไขหน้าเว็บหรือดูแลระบบ (GitHub / Cloudflare) | ก ง จ และ ซ              |
| ผู้ที่จะสร้างระบบใหม่ทั้งหมด                       | ก ฉ และ ซ                |
| ผู้สร้างระบบ และผู้รับมอบงานต่อ                    | ทุกส่วน โดยเฉพาะ ช และ ซ |

> ผู้ที่มีสิทธิ์ผู้ดูแลระบบ หรือมีบัญชี GitHub / Cloudflare ของระบบนี้ **ต้องอ่านส่วน ซ (ความปลอดภัย)** ทุกคน

## 2. ภาพรวมการทำงานของระบบ

```
เจ้าหน้าที่ (คอมพิวเตอร์ / มือถือ)
        │  เปิดเว็บผ่าน HTTPS
        ▼
Cloudflare  ── หน้าเว็บ + ระบบจอง + ฐานข้อมูล (ทำงานตลอด 24 ชั่วโมง ไม่ต้องเปิดเครื่องใดไว้)
        ▲
        │  ดึงโค้ดไปอัปเดตเว็บให้อัตโนมัติ ทุกครั้งที่มีการแก้ไขสาขา main
GitHub  ── โค้ดต้นฉบับของระบบ (github.com/MiminZeroX/-)
```

| สิ่งของ                                     | เก็บอยู่ที่                                     | หมายเหตุ                                      |
| ------------------------------------------- | ----------------------------------------------- | --------------------------------------------- |
| โค้ด หน้าเว็บ รูปภาพ คู่มือ                 | GitHub                                          | แก้ที่นี่แล้วเว็บอัปเดตเอง                    |
| ข้อมูลการจอง ผู้ใช้ บันทึกกิจกรรม ไฟล์สำรอง | Cloudflare (Durable Object ชื่อ `TunnelTarget`) | **ไม่อยู่ใน GitHub** — สำรองได้จากหน้าผู้ดูแล |
| รหัสผ่านเริ่มต้น/รีเซ็ตของผู้ดูแล           | Cloudflare › Variables and Secrets              | เป็นความลับ ห้ามใส่ใน GitHub                  |

> **คำเตือนสำคัญ:** ห้ามลบ Worker `bangrak-room-booking` ใน Cloudflare — ข้อมูลการจองทั้งหมดจะหายถาวร ถ้าจำเป็นต้องลบ ให้ดาวน์โหลดไฟล์สำรองก่อนทุกครั้ง

ระบบยังรันแบบติดตั้งบนเครื่องในสำนักงาน หรือเครื่องคลาวด์ (VM) ได้ด้วย (หัวข้อ 37) แต่คู่มือนี้เน้นแบบ Cloudflare ที่ใช้งานจริงอยู่

## 3. คำศัพท์ที่ควรรู้

| คำ                | ความหมายแบบง่าย                                                      |
| ----------------- | -------------------------------------------------------------------- |
| GitHub            | เว็บไซต์เก็บโค้ดต้นฉบับ พร้อมประวัติการแก้ไขทุกครั้ง                 |
| Repository (repo) | “โฟลเดอร์โครงการ” บน GitHub ของระบบนี้ คือ `MiminZeroX/-`            |
| Commit            | การบันทึกการแก้ไขหนึ่งครั้ง (มีข้อความอธิบาย ย้อนดูได้)              |
| Branch / `main`   | สายของการแก้ไข — `main` คือสายหลักที่ขึ้นเว็บจริง                    |
| Pull Request (PR) | คำขอนำการแก้ไขจากสายอื่นเข้า `main` ให้ตรวจก่อน                      |
| Merge             | รวมการแก้ไขเข้า `main` (เว็บจะอัปเดตหลังจากนี้)                      |
| Cloudflare        | บริการคลาวด์ที่รันเว็บนี้ ให้ HTTPS และลิงก์ถาวร                     |
| Worker            | โปรแกรมเว็บบน Cloudflare — ของระบบนี้ชื่อ `bangrak-room-booking`     |
| Deploy            | การนำเวอร์ชันใหม่ขึ้นเว็บจริง (Cloudflare ทำเองเมื่อ `main` เปลี่ยน) |
| Rollback          | ย้อนเว็บกลับไปเวอร์ชันก่อนหน้า                                       |
| Secret            | ค่าลับ (เช่น รหัสผ่าน) ที่ตั้งใน Cloudflare อ่านย้อนไม่ได้           |
| Durable Object    | ส่วนของ Cloudflare ที่รันระบบและเก็บข้อมูลการจอง                     |
| 2FA               | การยืนยันตัวตน 2 ขั้น (รหัสผ่าน + รหัสจากแอปในมือถือ)                |

# ภาษาไทย · ส่วน ข — สำหรับผู้ใช้ทั่วไป (เจ้าหน้าที่)

## 4. เปิดระบบและหน้าแรก

เปิดเบราว์เซอร์ (Chrome, Edge, Safari) แล้วพิมพ์ที่อยู่ของระบบ หรือสแกน QR Code ที่ติดในสำนักงาน

| รายการ                               | ของสำนักงาน (ผู้ดูแลกรอก)            |
| ------------------------------------ | ------------------------------------ |
| ที่อยู่ระบบ                          | \***\*\*\*\*\***\_\_\***\*\*\*\*\*** |
| ผู้ดูแลห้องประชุม / เบอร์ติดต่อภายใน | \***\*\*\*\*\***\_\_\***\*\*\*\*\*** |

![หน้าแรก](images/u-home.jpg)

- เมนูด้านบน: **หน้าแรก · ปฏิทินห้อง · จองห้อง · การจองของฉัน**
- แถบประกาศคือข้อความจากผู้ดูแล (กด × เพื่อซ่อน)
- กล่องตัวเลขบอกเวลา จำนวนการประชุมวันนี้ และห้องที่ว่างขณะนี้
- กด **จองห้องประชุม** เพื่อเริ่มจอง หรือ **ดูตารางห้อง** เพื่อเปิดปฏิทิน

เลื่อนลงจะเห็นการ์ดของแต่ละห้อง สถานะ **ว่าง / ไม่ว่าง / ใกล้เริ่มประชุม** แถบเวลาของวันนี้ (เส้นแดง = เวลาปัจจุบัน) และปุ่ม **จองห้องนี้**
ใต้ชื่อห้อง “**ยืนยันทันที**” = จองแล้วได้ห้องเลย, “**รอผู้ดูแลอนุมัติ**” = ต้องรออนุมัติ

![สถานะห้องประชุม](images/u-home-rooms.jpg)

ทุกหน้าจออัปเดตเองทันทีเมื่อมีคนจองหรือยกเลิก ไม่ต้องรีเฟรช

## 5. ดูตารางห้อง (ปฏิทิน)

![ปฏิทินรายสัปดาห์](images/u-calendar.jpg)

- เลือก **รายวัน / รายสัปดาห์ / รายเดือน** ที่มุมขวาบน และใช้ **‹ วันนี้ ›** เลื่อนวัน
- กรองห้องด้วย **ทุกห้อง / ห้องประชุมเล็ก / ห้องประชุมใหญ่**
- สีทึบ = **อนุมัติแล้ว** · ลายเส้น = **รออนุมัติ** · ลายเทา = **ปิดใช้ห้อง**
- **กดช่องว่าง** เพื่อจองเวลานั้นทันที · กดรายการเพื่อดูรายละเอียด · บนมือถือปัดซ้าย/ขวาเพื่อเปลี่ยนวัน

## 6. จองห้อง 3 ขั้นตอน

**ขั้นที่ 1 — ห้องและเวลา:** เลือกห้อง เลือกวันที่ (วันที่ขีดฆ่า = จองไม่ได้) แล้วเลือกช่วงเวลา โดยแตะช่องเวลาเริ่ม แล้วแตะช่องเวลาสุดท้าย หรือกดปุ่มระยะเวลา / ช่วงเช้า / ช่วงบ่าย / ทั้งวัน (ช่องลายขีด = ไม่ว่าง)

![ขั้นที่ 1 เลือกห้องและเวลา](images/u-book-1.jpg)

**ขั้นที่ 2 — รายละเอียด:** หัวข้อการประชุม\* ชื่อผู้จอง\* หน่วยงาน\* เบอร์โทร\* จำนวนผู้เข้าร่วม\* อุปกรณ์ บริการเสริม หมายเหตุ (\* = ต้องกรอก)

![ขั้นที่ 2 กรอกรายละเอียด](images/u-book-2.jpg)

- **จองซ้ำ:** เลือก **ทุกสัปดาห์** หรือ **ทุกวันทำการ** และจำนวนครั้ง ระบบตรวจห้องว่างให้ทุกวัน
- **จดจำชื่อ หน่วยงาน และเบอร์โทรไว้ในอุปกรณ์นี้** — ใช้กับเครื่องส่วนตัวเท่านั้น
- **นี่เป็นอุปกรณ์ส่วนกลาง** — ใช้เมื่อจองจากเครื่องที่คนอื่นใช้ร่วม (ระบบจะไม่เก็บการจองไว้ในเครื่องนั้น)

**ขั้นที่ 3 — ตรวจสอบและยืนยัน:** อ่านระเบียบการใช้ห้อง ติ๊กยอมรับ แล้วกด **ยืนยันการจอง**

![ขั้นที่ 3 ตรวจสอบและยืนยัน](images/u-book-3.jpg)

## 7. หลังจองเสร็จและสถานะการจอง

![จองห้องเรียบร้อย](images/u-success.jpg)

- ระบบแสดง **รหัสการจอง** เช่น `BR6910-5Y7M` — **ควรเก็บไว้**
- **เพิ่มลงปฏิทิน** (ไฟล์ .ics) · **พิมพ์ใบยืนยัน** (มี QR Code) · **ดูการจองของฉัน**

| สถานะ           | ความหมาย                                   |
| --------------- | ------------------------------------------ |
| **อนุมัติแล้ว** | ได้ห้องแล้ว                                |
| **รออนุมัติ**   | รอผู้ดูแลอนุมัติ (เวลานี้ถูกกันไว้ให้แล้ว) |
| **ไม่อนุมัติ**  | ผู้ดูแลไม่อนุมัติ (ดูเหตุผลในรายละเอียด)   |
| **ยกเลิก**      | ถูกยกเลิกโดยผู้จองหรือผู้ดูแล              |

ระบบไม่ส่งอีเมล/SMS — ดูสถานะได้ที่เมนู **การจองของฉัน**

## 8. การจองของฉัน: แก้ไข ยกเลิก พิมพ์

![การจองของฉัน](images/u-my.jpg)

| ปุ่ม                | ใช้ทำอะไร                                                                              |
| ------------------- | -------------------------------------------------------------------------------------- |
| **แก้ไข**           | เปลี่ยนเวลา ห้อง รายละเอียด (การจองที่อนุมัติแล้วอาจต้องรออนุมัติใหม่)                 |
| **เพิ่มลงปฏิทิน**   | บันทึกลงปฏิทินในเครื่อง                                                                |
| **พิมพ์**           | พิมพ์ใบยืนยัน                                                                          |
| **ยกเลิกการจอง**    | ระบุเหตุผลได้ — การจองซ้ำเลือก **เฉพาะครั้งนี้** หรือ **ครั้งนี้และครั้งถัดไปทั้งหมด** |
| **ลบจากอุปกรณ์นี้** | ซ่อนจากเครื่องนี้เท่านั้น **ไม่ได้ยกเลิกการจอง**                                       |

**ดูการจองจากเครื่องอื่น:** กรอก **รหัสการจอง** และ **เบอร์โทรที่ใช้จอง** แล้วกด **ค้นหาและเพิ่ม** (ใส่เบอร์ผิดหลายครั้ง ระบบจะพักการค้นหารหัสนั้น 1 ชั่วโมง)

**ไม่ใช้ห้องแล้ว กรุณายกเลิก** เพื่อให้หน่วยงานอื่นจองต่อได้

## 9. เช็คอิน คืนห้องก่อนเวลา และจอหน้าห้อง

ใช้เมื่อสำนักงานเปิดฟังก์ชันเช็คอิน:

- **เช็คอินเข้าใช้ห้อง** — กดได้ก่อนเวลาเริ่มเล็กน้อย จากการจองของฉันหรือจอหน้าห้อง
- ไม่เช็คอินภายในเวลาที่กำหนด **ระบบคืนห้องอัตโนมัติ**
- **คืนห้องก่อนเวลา** — ประชุมเสร็จเร็ว ระบบปรับเวลาสิ้นสุดเป็นเวลาปัจจุบัน

![จอแสดงผลหน้าห้อง](images/u-display.jpg)

จอแท็บเล็ตหน้าห้องแสดงสถานะตัวใหญ่ การประชุมปัจจุบัน กำหนดการวันนี้ ปุ่ม **จองห้องนี้** และ QR Code สำหรับจองด้วยมือถือ

# ภาษาไทย · ส่วน ค — สำหรับผู้ดูแลระบบ (หน้า admin)

## 11. เข้าสู่ระบบ บทบาท และรหัสผ่าน

เปิด `ที่อยู่ระบบ/admin` (หรือกด **สำหรับผู้ดูแลระบบ** ท้ายหน้าเว็บ)

![หน้าเข้าสู่ระบบผู้ดูแล](images/a-login.jpg)

| สิทธิ์          | ใช้ได้                                                |
| --------------- | ----------------------------------------------------- |
| **ผู้ดูแลระบบ** | ทุกเมนู                                               |
| **เจ้าหน้าที่** | แดชบอร์ด และรายการจอง (ดู เพิ่ม แก้ไข อนุมัติ ยกเลิก) |

- **ครั้งแรก:** บัญชี `admin` ใช้รหัสที่ตั้งไว้ใน Cloudflare (`ADMIN_INITIAL_PASSWORD` หรือ `ADMIN_RESET_PASSWORD` — หัวข้อ 27) แล้วระบบ **บังคับตั้งรหัสของตนเอง**
- ผู้ใช้ใหม่ได้ **รหัสผ่านชั่วคราว** จากผู้ดูแล และต้องตั้งรหัสใหม่เมื่อเข้าครั้งแรก
- รหัสผ่านอย่างน้อย **12 ตัวอักษร** ห้ามเดาง่าย ห้ามมีชื่อผู้ใช้ — แนะนำเป็นวลี เช่น `ห้องประชุม-ชั้นสี่-2569`
- ใส่รหัสผิดหลายครั้ง ระบบพักการเข้าสู่ระบบชั่วคราว · ออกจากระบบอัตโนมัติเมื่อไม่ใช้งาน (ค่าเริ่มต้น 12 ชั่วโมง)
- เปลี่ยนเครือข่าย (เช่น Wi-Fi ↔ 4G) ต้องเข้าสู่ระบบใหม่ — เป็นการป้องกันคุกกี้ถูกขโมย
- รายการสำคัญ (เพิ่มผู้ใช้ เปลี่ยนสิทธิ์ กู้คืนข้อมูล ฯลฯ) ต้อง **ยืนยันรหัสผ่านซ้ำ**

![ตั้งรหัสผ่านใหม่เมื่อเข้าครั้งแรก](images/a-first-login.jpg)

- กดรายการเพื่อ **อนุมัติ / ไม่อนุมัติ / แก้ไข / ยกเลิก** หรือ **ลบถาวร** (ใช้เฉพาะรายการทดสอบ — ยกเลิกจะเก็บประวัติไว้)

## 15. ผู้ใช้งานระบบ และบันทึกกิจกรรม

![เพิ่มผู้ใช้](images/a-users.jpg)

- **เพิ่มผู้ใช้:** ชื่อผู้ใช้ (ภาษาอังกฤษ) ชื่อ–นามสกุล สิทธิ์ รหัสผ่านชั่วคราว (กด **สุ่มรหัส** ได้) และรหัสผ่านของคุณเพื่อยืนยัน
- แจ้งรหัสชั่วคราวทาง **ช่องทางส่วนตัว** · เจ้าหน้าที่ย้ายงาน/ลาออก ให้ **ปิดการใช้งาน** ทันที
- ควรมี **ผู้ดูแลระบบอย่างน้อย 2 คน** และ **ใช้บัญชีของตนเองเท่านั้น ห้ามใช้บัญชีร่วม**

![บันทึกกิจกรรม](images/a-logs.jpg)

บันทึกทุกการจอง แก้ไข อนุมัติ เข้าสู่ระบบ (รวมครั้งที่ผิด) และการเปลี่ยนการตั้งค่า พร้อมเวลา ผู้ทำ IP อุปกรณ์ — กรองระดับ **ความปลอดภัย** เพื่อดูความผิดปกติ ส่งออก CSV ได้ (ระบบเก็บ 30 วันล่าสุดไว้เสมอ ลบย้อนหลังไม่ได้)

## 16. สำรอง/กู้คืนข้อมูล การเชื่อมต่อ และจอหน้าห้อง

![สำรองและกู้คืนข้อมูล](images/a-backup.jpg)

- **ดาวน์โหลดไฟล์สำรองตอนนี้** — ไฟล์ .json (การจอง ห้อง การตั้งค่า หน่วยงาน วันหยุด รายชื่อผู้ดูแล **ไม่รวมรหัสผ่าน**) ติ๊กรวม Log ได้
- **ไฟล์สำรองอัตโนมัติ** — วันละครั้ง เก็บตามจำนวนวันที่ตั้ง
- **กู้คืนจากไฟล์สำรอง** — แทนที่ข้อมูลปัจจุบัน (ระบบสำรองของเดิมให้ก่อน) ต้องยืนยันรหัสผ่าน — **บัญชีผู้ใช้ไม่ถูกแทนที่**
- ไฟล์สำรองมี **ข้อมูลส่วนบุคคล** (ชื่อ เบอร์โทร) — เก็บในที่ปลอดภัย (หัวข้อ 45)

![การเชื่อมต่อและ QR](images/a-connect.jpg)

- ที่อยู่สำหรับเข้าใช้งาน **IP ของคุณที่ระบบเห็น** (ใช้ตั้ง `OFFICE_IPS`) QR Code และ **พิมพ์โปสเตอร์ QR**
- **จอหน้าห้อง:** เปิดลิงก์จากหน้านี้บนแท็บเล็ต (มีรหัสจอฝังอยู่ ปุ่มเช็คอินจึงจะใช้ได้) ตั้งแท็บเล็ตไม่ให้ล็อกจอ เสียบสายชาร์จไว้ — แท็บเล็ตหายให้กด **สร้างรหัสใหม่**

## 17. ลบข้อมูล และล้างฐานข้อมูล

> **ก่อนลบทุกครั้ง:** กด **ดาวน์โหลดไฟล์สำรองตอนนี้** เก็บไว้ก่อน · การจองจริงที่ไม่ใช้แล้วให้กด **ยกเลิก** แทน **ลบ** เพื่อให้ยังมีประวัติ · การลบทุกแบบทำได้เฉพาะบัญชีสิทธิ์ **ผู้ดูแลระบบ** และถูกบันทึกใน Log

**ลบอะไร ทำที่ไหน**

| ------------------------------------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| การจอง 1 รายการ                             | **รายการจอง** › เปิดรายการ › **ลบถาวร**                                             | หายจากระบบทันที — ใช้กับรายการทดสอบหรือจองผิด                                                          |
| การจองหลายรายการ                            | **รายการจอง** › ติ๊กเลือก › **ลบถาวร**                                              | ครั้งละไม่เกิน 500 รายการ                                                                              |
| การจองเก่าก่อนวันที่กำหนด                   | **สำรอง/กู้คืนข้อมูล** › **ล้างข้อมูลการจอง** › **ลบการจองเก่า**                    | ลบเฉพาะการจองที่วันประชุมอยู่ก่อนวันที่เลือก (เลือกวันในอนาคตไม่ได้)                                   |

**ขั้นตอนล้างข้อมูลการจอง (ลบการจองเก่า / ล้างทั้งหมด)**

![ล้างการจองทั้งหมด: พิมพ์คำยืนยันและรหัสผ่าน](images/a-purge.jpg)

1. เมนู **สำรอง/กู้คืนข้อมูล** › **ดาวน์โหลดไฟล์สำรองตอนนี้** — เก็บไฟล์ไว้ในที่ปลอดภัย
2. การ์ด **ล้างข้อมูลการจอง** › เลือก **ลบการจองเก่า** (เลือกวันที่ เช่น 1 ม.ค. ของปีที่แล้ว) หรือ **ล้างการจองทั้งหมด** (พิมพ์ **ลบทั้งหมด**)
3. ใส่ **รหัสผ่านของคุณ** › กดปุ่มสีแดง — ระบบแจ้งจำนวนที่ลบ
4. ระบบสร้างไฟล์สำรอง **`prepurge-วันที่เวลา.json`** ไว้ในรายการไฟล์สำรองอัตโนมัติก่อนลบเสมอ และบันทึก Log หัวข้อ **ล้างข้อมูลการจอง**

**ลบผิด — กู้คืน:** **สำรอง/กู้คืนข้อมูล** › **ไฟล์สำรองอัตโนมัติ** › **ดาวน์โหลด** ไฟล์ `prepurge-…` › ลากไฟล์นั้นไปที่ **กู้คืนจากไฟล์สำรอง** › ใส่รหัสผ่าน — ข้อมูลกลับเป็นเหมือนก่อนลบ (การจองที่เกิดขึ้น **หลัง** การลบจะหายไป จึงควรกู้คืนทันทีที่รู้ตัว)

> **ข้อมูลส่วนบุคคล:** การจองที่ลบแล้วยังอยู่ในไฟล์สำรองอัตโนมัติอีกไม่เกินจำนวนวันที่ตั้ง (30 วัน) แล้วจึงหายหมด และยังอยู่ในไฟล์ที่เคยดาวน์โหลดไว้ — ต้องลบไฟล์เหล่านั้นเอง

## 27. ตั้งค่าลับ (Secrets) และค่าตั้ง (Variables)

**Settings › Variables and Secrets › + Add** › เลือก **Type** › ใส่ **Variable name** และ **Value** › **Deploy** (หรือ Save) — การบันทึกจะสร้างเวอร์ชันใหม่ของเว็บ **ข้อมูลไม่หาย**

| ชื่อ                     | ประเภท | ใช้ทำอะไร                                                                                                                                         |
| ------------------------ | ------ | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ADMIN_INITIAL_PASSWORD` | Secret | รหัสผ่านเริ่มต้นของ `admin` — ใช้ **เฉพาะตอนเปิดระบบครั้งแรกสุด** ต้องตั้งก่อนเปิดเว็บครั้งแรก                                                    |
| `ADMIN_RESET_PASSWORD`   | Secret | **ลืมรหัสผู้ดูแล:** ใส่รหัสใหม่ แล้วเปิดเว็บ — บัญชี `admin` ถูกรีเซ็ตเป็นรหัสนี้ **ครั้งเดียวต่อค่าที่ตั้ง** (ใส่ค่าเดิมซ้ำไม่มีผล) ลบได้หลังใช้ |
| `OFFICE_IPS`             | Text   | IP สาธารณะของสำนักงาน คั่นด้วย `,` — กันไม่ให้ทั้งสำนักงานถูกจำกัดพร้อมกัน (ดู IP ในหน้าผู้ดูแล › การเชื่อมต่อ)                                   |
| `PUBLIC_URL`             | Text   | ที่อยู่เว็บหลักเมื่อใช้โดเมนของหน่วยงาน เช่น `https://booking.example.go.th`                                                                      |

- ค่าประเภท **Secret** เมื่อบันทึกแล้วจะอ่านย้อนไม่ได้ (ปลอดภัย) — จดรหัสไว้ในที่ปลอดภัยของตนเอง
- ระบบ **ไม่เคยแสดงรหัสผ่านใน Logs**
- Secret ชื่อ `UPDATE_TOKEN` (ของระบบส่งต่อลิงก์รุ่นเก่า) **ไม่ใช้แล้ว ลบได้**

## 28. ตรวจว่าเว็บอัปเดตแล้ว และการย้อนเวอร์ชัน (Rollback)

- **ตรวจ:** แท็บ **Deployments** แสดงเวอร์ชันล่าสุดพร้อมเวลา — หรือดู ✓ สีเขียวข้าง commit ใน GitHub
- **ถ้า build ไม่สำเร็จ (✗):** Cloudflare **คงเว็บเวอร์ชันเดิมไว้** — กดดูรายละเอียดใน Workers & Pages › bangrak-room-booking › **Deployments** / **Builds** › **View logs** แล้วส่งข้อความ error ให้นักพัฒนา
- **Rollback:** **Deployments** › เลือกเวอร์ชันที่ใช้ได้ › เมนู **⋯** › **Rollback** › ยืนยัน — มีผลทันที (ข้อมูลไม่หาย)

## 29. ใช้โดเมนของหน่วยงาน (ไม่บังคับ)

1. โดเมนต้องอยู่ใน Cloudflare ก่อน: **Add a domain** แล้วเปลี่ยน Nameserver ตามที่ Cloudflare บอก (โดเมน `.go.th` ต้องประสานผู้ดูแลโดเมนของหน่วยงาน)
2. Worker › **Settings › Domains & Routes › + Add › Custom domain** › ใส่ เช่น `booking.example.go.th`
3. ตั้ง Variable `PUBLIC_URL` = `https://booking.example.go.th` แล้วพิมพ์โปสเตอร์ QR ใหม่

4. **แสดงไฟล์ที่ซ่อนอยู่** (ไฟล์ชื่อขึ้นต้นด้วยจุด เช่น `.gitignore`): Mac กด **Cmd + Shift + .** ใน Finder · Windows: File Explorer › **View** › **Show** › **Hidden items**

   - GitHub รับได้ครั้งละไม่เกิน 100 ไฟล์ — ถ้าเกิน ให้ลากโฟลเดอร์ `public` ก่อน แล้วค่อยลากส่วนที่เหลือในรอบที่สอง
6. ด้านล่างกด **Commit changes**
7. ตรวจ: หน้าแรกของ repository ต้องเห็น `public/`, `src/`, `worker/` และไฟล์ `wrangler.jsonc` **อยู่ชั้นบนสุด** (ไม่ได้อยู่ในโฟลเดอร์ซ้อนอีกชั้น)

# ภาษาไทย · ส่วน ซ — ความปลอดภัย

## 42. หลักสำคัญ 10 ข้อ

1. เปิด **2FA** ทุกบัญชี GitHub และ Cloudflare
2. **ห้ามใช้บัญชีร่วมกัน** — ทุกคนมีบัญชีของตนเอง
3. ให้สิทธิ์ **เท่าที่จำเป็น** (เจ้าหน้าที่ใช้สิทธิ์ “เจ้าหน้าที่” ไม่ใช่ “ผู้ดูแลระบบ”)
4. **รหัสผ่านและค่าลับอยู่ใน Cloudflare Secrets เท่านั้น** — ห้ามใส่ใน GitHub ไฟล์ แชท อีเมล หรือส่งให้ AI
5. repository เป็น **Private**
6. **ตรวจก่อน merge** — ห้าม merge สิ่งที่ไม่เข้าใจหรือจากคนที่ไม่รู้จัก
7. **สำรองข้อมูลทุกสัปดาห์** และเก็บไฟล์สำรองอย่างปลอดภัย (มีข้อมูลส่วนบุคคล)
8. **ปิดบัญชีคนที่ย้ายงาน/ลาออกทันที** ทั้งในระบบจอง GitHub และ Cloudflare
9. **ตรวจ Log ระดับความปลอดภัย** และรายชื่อสมาชิกเป็นประจำ
10. รู้ขั้นตอนเมื่อเกิดเหตุ (หัวข้อ 47) ก่อนที่จะเกิดเหตุ

## 43. บัญชีและรหัสผ่าน

- ใช้ **โปรแกรมจัดการรหัสผ่าน** และรหัสที่ไม่ซ้ำกันในแต่ละบริการ
- ใช้แอป Authenticator แทน SMS และเก็บ **Recovery codes** ไว้ในที่ปลอดภัย (ถ้ามือถือหาย จะกู้บัญชีได้)
- บัญชี GitHub / Cloudflare ของระบบควรผูกกับ **อีเมลของหน่วยงาน** ไม่ใช่อีเมลส่วนตัว
- ในระบบจอง: รหัส ≥ 12 ตัวอักษร · ออกจากระบบเมื่อใช้เครื่องส่วนกลาง · ไม่บันทึกรหัสในเบราว์เซอร์ของเครื่องส่วนกลาง

## 44. ค่าลับ (Secrets) และโค้ด

- รหัสที่ใส่ใน `ADMIN_INITIAL_PASSWORD` / `ADMIN_RESET_PASSWORD` เป็น **รหัสชั่วคราว** — ระบบบังคับตั้งใหม่ทันทีเมื่อเข้าสู่ระบบ
- ถ้าเผลอเปิดเผยรหัสหรือ Token: **เปลี่ยน/ลบทันที** (Cloudflare › My Profile › **API Tokens** › Roll/Delete)
- อย่าสร้าง API Token ถ้าไม่จำเป็น ถ้าต้องสร้างให้ใช้สิทธิ์น้อยที่สุดและกำหนดวันหมดอายุ
- ติดตั้งแอปเข้าบัญชี GitHub เฉพาะที่รู้จัก (Cloudflare) · ตรวจ **Settings › Applications** เป็นระยะ
- **ห้ามนำไฟล์สำรองหรือโฟลเดอร์ `data/` ขึ้น GitHub**

## 45. ข้อมูลส่วนบุคคล (PDPA) และไฟล์สำรอง

- ระบบเก็บ: ชื่อผู้จอง หน่วยงาน เบอร์โทร (และอีเมลถ้าเปิด) หัวข้อการประชุม IP และอุปกรณ์ใน Log
- ปฏิทินสาธารณะ **ไม่แสดงเบอร์โทร/อีเมลเสมอ** — ปิดการแสดงชื่อผู้จองได้ในหมวดความเป็นส่วนตัว
- ตั้งระยะเวลาเก็บ Log และไฟล์สำรองอัตโนมัติให้เหมาะสม (หน้าตั้งค่า › ระบบและความปลอดภัย)
- **เก็บข้อมูลเท่าที่จำเป็น:** กำหนดระยะเก็บการจองร่วมกับ DPO (เช่น 1–2 ปี) แล้ว **ลบการจองเก่า** ทุกปี — ระบบไม่ลบการจองให้เอง (หัวข้อ 17)
- ไฟล์สำรองที่ดาวน์โหลด: เก็บในไดรฟ์ของหน่วยงานที่จำกัดสิทธิ์ หรือเข้ารหัส · ลบไฟล์เก่าที่ไม่ใช้ · ไม่ส่งผ่านแชท
- แจ้งเจ้าหน้าที่คุ้มครองข้อมูลส่วนบุคคล (DPO) / ฝ่ายเทคโนโลยีสารสนเทศของหน่วยงานว่าข้อมูลอยู่บน Cloudflare

## 46. สิ่งที่ระบบป้องกันให้แล้ว

- HTTPS ทุกการเชื่อมต่อ · header ความปลอดภัยครบ (CSP, nosniff, frame) ทุกหน้า
- รหัสผ่านเข้ารหัสแบบ scrypt · บังคับเปลี่ยนรหัสครั้งแรก · นโยบายรหัสผ่าน · จำกัดการเดารหัสทั้งต่อ IP และต่อบัญชี
- คุกกี้ HttpOnly + Secure + SameSite=Strict ผูกกับ IP · ยืนยันรหัสซ้ำก่อนรายการสำคัญ
- กัน CSRF (รับเฉพาะ JSON + header เฉพาะ) · escape ข้อมูลทุกจุด (กัน XSS) · จำกัดขนาดข้อมูลและความถี่การใช้งาน
- ปฏิทินสาธารณะไม่เปิดเผยรหัสการจองและข้อมูลติดต่อ · รหัสการจองแบบสุ่ม · ค้นหาด้วยเบอร์ผิดซ้ำถูกพัก
- ไฟล์สำรองที่ดาวน์โหลดไม่มีแฮชรหัสผ่าน · Log 30 วันล่าสุดลบไม่ได้ · ไม่มีรหัสผ่านใน Log ของ Cloudflare
- ระบบผ่านการทดสอบเจาะระบบและตรวจโค้ดตาม OWASP Top 10 และมีชุดทดสอบอัตโนมัติ 51 กรณี

**ทางเลือกเพิ่มความปลอดภัย:** ใช้ **Cloudflare Access** (Zero Trust › Access › Applications) จำกัดให้เฉพาะอีเมลของหน่วยงานเปิดหน้า `/admin*` และ `/api/admin/*` ได้ (ฟรีสำหรับผู้ใช้ไม่เกิน 50 คน)

## 47. เมื่อสงสัยว่าถูกเจาะหรือเกิดเหตุผิดปกติ

1. **ตั้งสติและจดบันทึก:** เวลา สิ่งที่พบ ภาพหน้าจอ
2. **ปิดรับการจองชั่วคราว** (ตั้งค่า › ระบบและความปลอดภัย) ถ้าข้อมูลถูกแก้ไขผิดปกติ

4. **ตรวจ Log** ระดับความปลอดภัย (เข้าสู่ระบบผิดซ้ำ เซสชันจาก IP อื่น การเปลี่ยนการตั้งค่า)

7. **กู้คืนข้อมูล** จากไฟล์สำรองก่อนเกิดเหตุ ถ้าข้อมูลเสียหาย
8. **รายงาน:** แจ้งผู้บังคับบัญชาและ DPO — ถ้าข้อมูลส่วนบุคคลรั่วไหล ต้องแจ้งสำนักงานคณะกรรมการคุ้มครองข้อมูลส่วนบุคคล (สคส.) **ภายใน 72 ชั่วโมง** ตาม PDPA

The online meeting room booking system of Bang Rak District Office, for the **Small Meeting Room (2nd floor)** and the **Large Meeting Room (4th floor)**.

## 2. How the system fits together

```
Staff (computer / phone)
        │  opens the site over HTTPS
        ▼
Cloudflare  ── web pages + booking system + database (24/7, no office machine needed)
        ▲
        │  pulls the code and updates the site automatically whenever `main` changes
GitHub  ── the system's source code (github.com/MiminZeroX/-)
```

| What                                    | Where it lives                                   | Note                                             |
| --------------------------------------- | ------------------------------------------------ | ------------------------------------------------ |
| Code, pages, images, manuals            | GitHub                                           | Edit here; the site updates itself               |
| Bookings, users, activity log, backups  | Cloudflare (Durable Object named `TunnelTarget`) | **Not in GitHub** — back up from the admin pages |
| Initial / reset administrator passwords | Cloudflare › Variables and Secrets               | Secret; never put them in GitHub                 |

> **Important:** never delete the `bangrak-room-booking` Worker in Cloudflare — all booking data would be lost permanently. If it must be deleted, download a backup first.

The system can also run on an office computer or a cloud VM (section 37), but this manual focuses on the Cloudflare setup that is in production.

## 3. Words you need to know

| Word              | Plain meaning                                                                 |
| ----------------- | ----------------------------------------------------------------------------- |
| GitHub            | Website that stores the source code with the full history of every change     |
| Repository (repo) | The project “folder” on GitHub — this one is `MiminZeroX/-`                   |
| Commit            | One saved change, with a short description you can look back at               |
| Branch / `main`   | A line of changes — `main` is the line that runs the live site                |
| Pull Request (PR) | A request to bring changes from another branch into `main`, reviewed first    |
| Merge             | Bring changes into `main` (the site updates afterwards)                       |
| Cloudflare        | Cloud service that runs the site, with HTTPS and a permanent link             |
| Worker            | A program on Cloudflare — this system’s is `bangrak-room-booking`             |
| Deploy            | Putting a new version live (Cloudflare does it when `main` changes)           |
| Rollback          | Returning the site to an earlier version                                      |
| Secret            | A hidden value (such as a password) set in Cloudflare; it cannot be read back |
| Durable Object    | The part of Cloudflare that runs the system and stores the bookings           |
| 2FA               | Two-factor authentication (password + a code from a phone app)                |

# English · Part H — Security

## 42. Ten key rules

1. **2FA** on every GitHub and Cloudflare account
2. **No shared accounts** — everyone has their own
3. **Least privilege** (staff get the “Staff” role, not “Administrator”)
4. **Passwords and secrets live only in Cloudflare Secrets** — never in GitHub files, chats, e-mail, or AI tools
5. The repository is **Private**
6. **Review before merging** — never merge what you don’t understand or from people you don’t know
7. **Back up weekly** and store backups securely (they contain personal data)
8. **Remove leavers immediately** from the booking system, GitHub and Cloudflare
9. **Review security log entries** and member lists regularly
10. Know the incident steps (section 47) before an incident happens

## 43. Accounts and passwords

- Use a **password manager** and a unique password per service
- Prefer an authenticator app over SMS, and keep the **recovery codes** safe (to recover the account if the phone is lost)
- GitHub / Cloudflare accounts for this system should use an **organisation e-mail**, not a personal one
- In the booking system: passwords ≥ 12 characters · sign out on shared computers · don’t save passwords in shared browsers

## 44. Secrets and code

- Values in `ADMIN_INITIAL_PASSWORD` / `ADMIN_RESET_PASSWORD` are **temporary** — the system forces a new password at sign-in
- If a password or token leaks: **change/delete it immediately** (Cloudflare › My Profile › **API Tokens** › Roll/Delete)
- Don’t create API tokens unless needed; if you must, give the least permissions and an expiry date
- Install only known apps into GitHub (Cloudflare) · review **Settings › Applications** regularly
- **Never upload backups or a `data/` folder to GitHub**

## 45. Personal data (Thailand PDPA) and backups

- Stored: requester names, departments, phone numbers (and e-mail if enabled), meeting titles, IP and device in the log
- The public calendar **never shows phone or e-mail**; requester names can be hidden under Privacy settings
- Set retention for the log and automatic backups appropriately (Settings › System & security)
- **Keep only what is needed:** agree a retention period for bookings with the DPO (e.g. 1–2 years) and **delete old bookings** every year — bookings are never deleted automatically (section 17)
- Downloaded backups: keep them on an access-restricted organisation drive or encrypted · delete old ones · never send them through chat
- Inform the organisation’s Data Protection Officer (DPO) / IT that the data is on Cloudflare

## 46. Protections already built in

- HTTPS everywhere · full security headers (CSP, nosniff, framing) on every page
- scrypt password hashing · forced change on first sign-in · password policy · guessing limits per IP and per account
- HttpOnly + Secure + SameSite=Strict cookies bound to the IP · re-authentication for sensitive actions
- CSRF protection (JSON only + custom header) · output escaping everywhere (XSS) · size and rate limits
- The public calendar hides booking codes and contact details · random booking codes · repeated wrong lookups paused
- Downloaded backups contain no password hashes · the latest 30 days of logs cannot be deleted · no passwords in Cloudflare logs
- Penetration-tested and reviewed against the OWASP Top 10, with 51 automated tests

**Optional hardening:** use **Cloudflare Access** (Zero Trust › Access › Applications) to allow only organisation e-mail addresses to open `/admin*` and `/api/admin/*` (free for up to 50 users).

## 47. Suspected breach or unusual activity

1. **Stay calm and record:** time, what you saw, screenshots
2. **Close bookings temporarily** (Settings › System & security) if data is being changed abnormally
3. **Reset the administrator password:** set a new `ADMIN_RESET_PASSWORD` › sign in › set a new password · **deactivate suspicious accounts** under Users
4. **Review the log** at security level (repeated failed sign-ins, sessions from another IP, settings changes)
5. **Generate a new door-display key** (Connection and QR) if a tablet is lost or suspect
6. Change GitHub / Cloudflare passwords · review Members, Collaborators and API tokens · check recent commits for anything unexpected (if found: Rollback + Revert — section 23)
7. **Restore** from a backup taken before the incident if data was damaged
8. **Report** to management and the DPO — if personal data leaked, notify Thailand’s Personal Data Protection Committee office (PDPC) **within 72 hours** under the PDPA

## 48. Troubleshooting

| Symptom                                            | What to do                                                                                                             |
| -------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| The site does not open at all                      | Check the link (`.workers.dev`) · Cloudflare › Deployments shows a recent version? · after a code change, try Rollback |
| Edited a file on GitHub but the site didn’t change | Wait 1–2 minutes and refresh · check ✓/✗ next to the commit — ✗ = build failed, see View logs (section 28)             |
| Cannot sign in as admin / forgot password          | Set `ADMIN_RESET_PASSWORD` to a **new value** and open the site (a reused value does nothing)                          |
| Error 1102 after signing in                        | Switch to Workers Paid (section 30)                                                                                    |
| The whole office is limited at once                | Set `OFFICE_IPS` (section 27)                                                                                          |
| Administrators get signed out often                | The network’s IP changes (mobile data) — by design, sign in again                                                      |
| Data missing / wrong                               | Admin › Backup/Restore › restore from an automatic or downloaded backup                                                |
| ✗ on a Pull Request (Workers Builds)               | Trial build for non-main branches; the live site is unaffected (section 30)                                            |
| Pages look broken after editing `js.js`            | Probably a code character was deleted — Rollback now, then revert the edit (section 23)                                |

_This manual matches the version running on Cloudflare (October 2026). Screenshots use sample data._
