# ระบบจองห้องประชุม · สำนักงานเขตบางรัก

เว็บไซต์ภายในองค์กรสำหรับจอง **ห้องประชุมเล็ก ชั้น 2** และ **ห้องประชุมใหญ่ ชั้น 4**
เปิดใช้ผ่าน Wi-Fi/LAN ของสำนักงานได้ทันที — ไม่ต้องติดตั้งแอป ใช้ได้ทั้งคอมพิวเตอร์ แท็บเล็ต และมือถือ

- ไม่ต้องใช้อินเทอร์เน็ต (ฟอนต์ ไอคอน SVG และ QR Code อยู่ในเครื่องทั้งหมด)
- เว็บหลายหน้า (HTML แยกตามหน้า) ใช้ไฟล์สไตล์ `css.css` และสคริปต์ `js.js` ร่วมกันเพียงอย่างละไฟล์
- ไอคอนทั้งหมดเป็น SVG — ไม่มีรูปภาพไอคอนหรืออีโมจิ
- ไม่ต้องติดตั้งฐานข้อมูลหรือแพ็กเกจเพิ่ม — ต้องการแค่ **Node.js** (รุ่น 18 ขึ้นไป)
- ข้อมูลเก็บเป็นไฟล์ในโฟลเดอร์ `data/` และสำรองอัตโนมัติทุกวัน

## เริ่มใช้งาน (ประมาณ 5 นาที)

### 1) ติดตั้ง Node.js บนเครื่องที่จะเป็น “เครื่องแม่ข่าย”

ดาวน์โหลดรุ่น **LTS** จาก <https://nodejs.org> แล้วติดตั้งตามขั้นตอนปกติ
(เครื่องแม่ข่ายคือคอมพิวเตอร์ที่เปิดทิ้งไว้ในสำนักงาน และเชื่อม Wi-Fi/LAN เดียวกับผู้ใช้)

### 2) เปิดระบบ

| ระบบปฏิบัติการ | วิธีเปิด                                           |
| -------------- | -------------------------------------------------- |
| Windows        | ดับเบิลคลิก **`start-windows.bat`**                |
| macOS / Linux  | เปิด Terminal ในโฟลเดอร์นี้ แล้วพิมพ์ `./start.sh` |

หน้าต่างจะแสดงที่อยู่สำหรับเข้าใช้งาน เช่น

```
เปิดจากเครื่องอื่นที่เชื่อม Wi-Fi/LAN เดียวกัน:
     http://192.168.1.25:3000
หน้าผู้ดูแลระบบ :  http://192.168.1.25:3000/admin.html
จอแสดงผลหน้าห้อง:  http://192.168.1.25:3000/display.html
```

> ครั้งแรกที่เปิดบน Windows อาจมีหน้าต่าง **Windows Defender Firewall** ถามสิทธิ์ ให้กด **Allow access** (เลือก Private networks)

### 3) เข้าใช้งาน

- **ผู้ใช้ทั่วไป**: เปิดเบราว์เซอร์ (Chrome, Edge, Safari) แล้วพิมพ์ที่อยู่ที่แสดง เช่น `http://192.168.1.25:3000`
  หรือสแกน QR Code (พิมพ์โปสเตอร์ได้จากเมนู “การเชื่อมต่อและ QR” ในหน้าผู้ดูแล)
- **ผู้ดูแลระบบ**: ไปที่ `admin.html` (หรือพิมพ์ `/admin`) ด้วยชื่อผู้ใช้ `admin`
  และ **รหัสผ่านเริ่มต้นแบบสุ่ม** ที่แสดงบนหน้าต่างระบบตอนเปิดครั้งแรก (บันทึกไว้ที่ `data/initial-admin-password.txt` ด้วย)
  ระบบจะให้ตั้งรหัสผ่านของตนเองก่อนใช้งานเมนูใด ๆ และลบไฟล์นั้นให้อัตโนมัติ
- **มือถือ/แท็บเล็ต**: กดเมนู “เพิ่มไปยังหน้าจอหลัก” (Add to Home Screen) จะได้ไอคอนเหมือนแอป

### ตั้งให้เปิดเองอัตโนมัติเมื่อเปิดเครื่อง (Windows)

ดับเบิลคลิก **`windows-autostart.bat`** หนึ่งครั้ง ระบบจะสร้าง shortcut ในโฟลเดอร์ Startup
(ยกเลิกได้โดยลบ `BangRak-Room-Booking.lnk` ใน `shell:startup`)
สคริปต์ `start-windows.bat` จะเริ่มระบบใหม่ให้อัตโนมัติหากหยุดทำงาน

## ความสามารถ

### สำหรับผู้จอง

- **หน้าแรก**: สถานะห้องแบบสด (ว่าง / กำลังใช้งาน / ใกล้เริ่ม) แถบเวลาของวัน นาฬิกา และกำหนดการวันนี้
- **ปฏิทิน**: มุมมองรายวัน รายสัปดาห์ รายเดือน กรองตามห้อง เส้นบอกเวลาปัจจุบัน
  คลิกช่องว่างเพื่อจองทันที ปัดซ้าย/ขวาบนมือถือเพื่อเปลี่ยนวัน
- **จองห้อง 3 ขั้นตอน**: เลือกห้อง วัน และช่วงเวลา (แตะเวลาเริ่มและเวลาสิ้นสุด หรือกดปุ่มระยะเวลา/ช่วงเช้า/บ่าย/ทั้งวัน)
  จากนั้นกรอกรายละเอียด (อุปกรณ์ บริการเสริม จำนวนผู้เข้าร่วมพร้อมแถบความจุห้อง) แล้วยืนยัน
- **จองซ้ำ** ทุกสัปดาห์หรือทุกวันทำการ พร้อมตรวจสอบห้องว่างล่วงหน้าทุกวัน
- **การจองของฉัน**: แก้ไข ยกเลิก (ยกเลิกเฉพาะครั้งหรือทั้งชุด) เช็คอิน คืนห้องก่อนเวลา
  เพิ่มลงปฏิทินมือถือ (.ics) พิมพ์ใบยืนยันการจองพร้อม QR Code
- ค้นหาการจองจากเครื่องอื่นด้วย **รหัสการจอง + เบอร์โทร**
- ข้อมูลอัปเดตสดทุกหน้าจอทันทีที่มีการจอง/ยกเลิก (ไม่ต้องกดรีเฟรช)

### เอฟเฟกต์และการตอบสนอง

- ทรานซิชันเปลี่ยนหน้า (ทิศทางตามการเลื่อนวัน) ขั้นตอนจองเลื่อนซ้าย/ขวา
- ripple และการยุบตัวเมื่อกดปุ่มทุกปุ่ม, การสั่นเบา ๆ บนมือถือ Android, เสียงคลิก (เปิด/ปิดได้)
- การ์ดลอยขึ้นตามลำดับ (stagger), ตัวเลขนับขึ้น, เครื่องหมายถูกวาดเส้น และพลุกระดาษเมื่อจองสำเร็จ
- bottom sheet ลากลงเพื่อปิดบนมือถือ, สั่นเตือนเมื่อกรอกข้อมูลผิด
- ผู้ดูแลกำหนดระดับเอฟเฟกต์ได้ (เต็มรูปแบบ / เรียบง่าย / ปิด) และผู้ใช้ปรับเองได้ — เคารพการตั้งค่า “ลดการเคลื่อนไหว” ของอุปกรณ์
- ดีไซน์โทนสะอาดแบบหน้าเว็บผลิตภัณฑ์: ตัวอักษรใหญ่ ปุ่มทรงแคปซูล แถบเมนูโปร่งแสง การ์ดห้องแบบการ์ดสินค้า
- ธีมสว่าง/มืด และสีหลัก 8 แบบ (ค่าเริ่มต้นสีน้ำเงิน)

### จอแสดงผลหน้าห้อง (`display.html`)

สำหรับแท็บเล็ตติดหน้าห้อง: สถานะห้องตัวใหญ่ การประชุมปัจจุบันพร้อมแถบความคืบหน้า กำหนดการวันนี้
ปุ่มเช็คอิน และ QR Code สำหรับจองด้วยมือถือ — `display.html?room=small-2` (ห้องเล็ก), `display.html?room=large-4` (ห้องใหญ่), `display.html` (ทุกห้อง)

ปุ่มเช็คอินบนจอใช้ได้เฉพาะแท็บเล็ตที่เปิดจาก **ลิงก์ในเมนู “การเชื่อมต่อและ QR”** (ลิงก์มีรหัสจอฝังอยู่)
หากแท็บเล็ตหายหรือสงสัยว่ารหัสรั่ว ให้กด “สร้างรหัสใหม่” แล้วเปิดลิงก์ใหม่บนจอทุกเครื่อง

## ตัวเลือกการเปิดระบบ

```bash
node server.js --port=8080          # เปลี่ยนพอร์ต (ค่าเริ่มต้น 3000)
node server.js --data=D:\booking    # เปลี่ยนโฟลเดอร์เก็บข้อมูล
node server.js --allowed-hosts=booking.bangrak.local   # ชื่อโดเมนภายในที่ใช้เปิดระบบ (นอกจาก IP/ชื่อเครื่อง)
node server.js --tls-cert=cert.pem --tls-key=key.pem   # เปิด HTTPS
```

หรือใช้ตัวแปรแวดล้อม `PORT`, `HOST`, `DATA_DIR`, `ALLOWED_HOSTS`, `TLS_CERT`, `TLS_KEY`

### เปิดใช้ผ่านอินเทอร์เน็ต (เครื่องคลาวด์ + HTTPS)

ดูขั้นตอนใน [deploy/README.md](deploy/README.md) — สคริปต์ `deploy/install-vm.sh` ติดตั้งทุกอย่างบน VM Ubuntu ให้ในคำสั่งเดียว
(HTTPS อัตโนมัติ, เริ่มระบบเองเมื่อเปิดเครื่อง, ไฟร์วอลล์) ตัวเลือกที่ใช้ในโหมดนี้:

```bash
--public-url=https://booking.example.go.th   # ที่อยู่ที่ผู้ใช้เปิด (ใช้ทำลิงก์/QR และเปิดคุกกี้แบบ Secure)
--trust-proxy=loopback                       # รับ IP จริงของผู้ใช้จาก proxy ด้านหน้า (Caddy/Nginx)
--office-ips=203.0.113.10                    # IP สาธารณะของสำนักงาน ที่ทุกคนใช้ร่วมกัน
```

หรือตัวแปร `PUBLIC_URL`, `TRUST_PROXY`, `OFFICE_IPS`

### เปิดใช้ HTTPS (แนะนำเมื่อ Wi-Fi ใช้ร่วมกับผู้มาติดต่อ)

HTTP ธรรมดาอาจถูกดักอ่านรหัสผ่านผู้ดูแลได้บนเครือข่ายที่ใช้ร่วมกัน วิธีที่ง่ายที่สุดคือใช้ [mkcert](https://github.com/FiloSottile/mkcert)
สร้างใบรับรองสำหรับ IP ของเครื่องแม่ข่าย แล้วติดตั้งใบรับรองหลัก (root CA) ให้เครื่องของเจ้าหน้าที่ หรือใช้ใบรับรองจากหน่วยงานด้านไอทีของ กทม.

```bash
mkcert 192.168.1.25 localhost       # ได้ไฟล์ 192.168.1.25+1.pem และ 192.168.1.25+1-key.pem
node server.js --port=443 --tls-cert=192.168.1.25+1.pem --tls-key=192.168.1.25+1-key.pem
```

เมื่อเปิด HTTPS คุกกี้เข้าสู่ระบบจะถูกส่งเฉพาะผ่านการเชื่อมต่อที่เข้ารหัสเท่านั้น (Secure)

### ชื่อโดเมนภายใน

ระบบรับคำขอที่เปิดผ่าน IP, `localhost` และชื่อเครื่องเท่านั้น (กันเว็บภายนอกหลอกใช้ระบบผ่านการ DNS rebinding)
หากหน่วยงานตั้งชื่อโดเมนภายใน เช่น `booking.bangrak.local` ให้เพิ่มด้วย `--allowed-hosts=` (คั่นหลายชื่อด้วยจุลภาค, ใช้ `*.office.lan` ได้)

## ข้อมูลและการสำรอง

| ไฟล์             | เนื้อหา                                                                           |
| ---------------- | --------------------------------------------------------------------------------- |
| `data/db.json`   | การจอง ห้อง การตั้งค่า หน่วยงาน วันหยุด บัญชีผู้ดูแล (รหัสผ่านเข้ารหัสแบบ scrypt) |
| `data/logs.json` | บันทึกกิจกรรม (ลบอัตโนมัติเมื่อเกินระยะเวลาที่ตั้งไว้)                            |
| `data/backups/`  | ไฟล์สำรองอัตโนมัติรายวัน และไฟล์สำรองก่อนการกู้คืน                                |

ไฟล์สำรองที่ **ดาวน์โหลด** จากหน้าผู้ดูแลจะไม่มีแฮชรหัสผ่าน และการกู้คืนจะไม่แทนที่บัญชีผู้ใช้ (ต้องใส่รหัสผ่านของผู้ดูแลเพื่อยืนยันทุกครั้ง)
ข้อมูลในไฟล์สำรองถูกตรวจด้วยกฎเดียวกับการบันทึกปกติ ค่าที่ผิดกฎจะใช้ค่าเริ่มต้นแทน และบันทึกกิจกรรมที่นำเข้าจะเพิ่มต่อจากของเดิม

ย้ายเครื่องแม่ข่าย: คัดลอกทั้งโฟลเดอร์ (รวม `data/`) ไปเครื่องใหม่ หรือใช้เมนูสำรอง/กู้คืนข้อมูล

## ความปลอดภัย

ทดสอบเจาะระบบ (penetration test) และตรวจโค้ดตาม OWASP Top 10 แล้ว — ผลการแก้ไขสรุปได้ดังนี้

**บัญชีและการเข้าสู่ระบบ**

- ไม่มีรหัสผ่านเริ่มต้นตายตัว: สุ่มใหม่ทุกการติดตั้ง และต้องตั้งรหัสของตนเองก่อนใช้ API ผู้ดูแลใด ๆ (เซิร์ฟเวอร์บังคับ ไม่ใช่แค่หน้าจอ)
- นโยบายรหัสผ่าน: อย่างน้อย 12 ตัวอักษร ไม่อยู่ในรายการรหัสที่เดาง่าย (รวมแบบเติมตัวเลข/สัญลักษณ์ เช่น `Password1234`, `bangrak@2569`) ไม่มีชื่อผู้ใช้อยู่ในรหัส
  รหัสเดิมที่ไม่ผ่านเกณฑ์จะถูกบังคับให้ตั้งใหม่เมื่อเข้าสู่ระบบ
- แฮชรหัสผ่านด้วย scrypt (N=2¹⁵, r=8, p=3) ทำงานแบบไม่บล็อกเซิร์ฟเวอร์ และอัปเกรดแฮชรุ่นเก่าอัตโนมัติ
- จำกัดการเดารหัสทั้งต่อ IP และต่อบัญชี (การเข้าสู่ระบบบัญชีอื่นสำเร็จไม่ล้างตัวนับ) และเวลาตอบเท่ากันไม่ว่าชื่อผู้ใช้มีจริงหรือไม่
- คุกกี้เซสชัน HttpOnly + SameSite=Strict (+ Secure เมื่อเปิด HTTPS) ผูกกับ IP ที่เข้าสู่ระบบ มีอายุสูงสุด และถูกยกเลิกทันทีหากถูกนำไปใช้จากเครื่องอื่น
- รายการสำคัญต้องยืนยันรหัสผ่านซ้ำ: เพิ่มผู้ใช้ เปลี่ยนสิทธิ์ ตั้งรหัสให้ผู้อื่น กู้คืนข้อมูล สร้างรหัสจอใหม่ (ผิดหลายครั้ง = ออกจากระบบทุกอุปกรณ์)

**การจองและข้อมูลส่วนบุคคล**

- ปฏิทินสาธารณะและการแจ้งเตือนสดไม่แสดงรหัสการจอง เบอร์โทร อีเมล หรือชื่อบัญชีผู้ดูแล
- รหัสการจองเป็นแบบสุ่ม (เดาลำดับไม่ได้) และค้นหาด้วยเบอร์ผิดซ้ำ ๆ จะพักรหัสนั้น 1 ชั่วโมง
- จำกัดการจองตามจำนวนรายการจริง (การจองซ้ำหลายวันนับทุกวัน) และจำนวนการจองค้างต่ออุปกรณ์
- แก้ไขเนื้อหาหลังได้รับอนุมัติแล้ว ต้องกลับไปรออนุมัติใหม่
- เช็คอินได้เฉพาะผู้จอง หรือจอหน้าห้องที่มีรหัสจอ
- อุปกรณ์ส่วนกลางเลือก “ไม่ต้องเก็บการจองไว้ในอุปกรณ์นี้” ได้ และระบบไม่จำข้อมูลผู้จองโดยอัตโนมัติ

**เว็บและเซิร์ฟเวอร์**

- Content-Security-Policy (`script-src 'self'`, `form-action 'self'`), COOP/CORP, Permissions-Policy, nosniff, X-Frame-Options ทุกการตอบกลับ (รวมการเปลี่ยนเส้นทาง)
- escape ข้อมูลทุกจุดที่แสดงผล (ทดสอบ XSS ในเบราว์เซอร์ครบทุกหน้า) ข้อความบรรทัดเดียวตัดการขึ้นบรรทัดและอักขระกลับทิศ (กันปลอม Log/CSV) และ CSV กันสูตร Excel
- โลโก้ SVG ที่มีสคริปต์หรือลิงก์ภายนอกถูกปฏิเสธ
- กัน CSRF (ต้องมี header เฉพาะ + รับเฉพาะ JSON), กัน DNS rebinding (ตรวจชื่อโฮสต์), กันเข้าถึงไฟล์นอก `public/` (เสิร์ฟเฉพาะชื่อไฟล์ที่มีจริงตรงตัว)
- กันการโจมตีให้ระบบล่ม: ตรวจสิทธิ์ก่อนรับข้อมูลขนาดใหญ่, ปฏิเสธข้อมูลเกินขนาดทันที, จำกัดเวลารับคำขอ, จำกัดการเชื่อมต่อสดต่ออุปกรณ์
- เก็บบันทึกกิจกรรม 30 วันล่าสุดไว้เสมอ (ลบย้อนหลังไม่ได้) ไฟล์ข้อมูลอ่านได้เฉพาะบัญชีที่รันระบบ

ระบบออกแบบสำหรับเครือข่ายภายใน — **ห้ามเปิดพอร์ตของระบบสู่อินเทอร์เน็ตโดยตรง** หากต้องการใช้ผ่านอินเทอร์เน็ต ให้ติดตั้งตาม [deploy/README.md](deploy/README.md) (HTTPS + proxy) และแนะนำให้เปิด HTTPS หาก Wi-Fi ใช้ร่วมกับผู้มาติดต่อ
